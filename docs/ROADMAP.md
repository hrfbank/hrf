# خارطة طريق حروف

> مستخلصة من مواصفات منصة مسابقات خليجية أرسلها المستخدم (2026-11-10)، ومكيّفة لحروف.
> **ما ننسخه:** لا شي من شكل أو أسماء أو محتوى أي تطبيق آخر. **ما ناخذه:** أفكار تجربة اللعب والتشغيل التجاري.

## قرارات تقنية (ليش ما نغيّر التقنية)
المستند يقترح Next.js + Prisma لمشروع جديد. مشروعنا قائم على **Vite + React + Supabase**، وهذا يغطي المطلوب:
| المطلوب | عندنا |
|---|---|
| قاعدة بيانات PostgreSQL | Supabase (Postgres) |
| مصادقة آمنة، Google/Apple، بريد، OTP | Supabase Auth |
| صلاحيات وأمان على الخادم | Row Level Security + دوال Postgres |
| تخزين وسائط | Supabase Storage (متوافق مع S3) |
| API | Supabase REST + Edge Functions للدفع والـ Webhooks |
| PWA و RTL و Responsive | Vite + الموجود |
| جرس الجوال اللحظي | Supabase Realtime |

## ما يختلف في حروف (ما ناخذه)
- **لوحة النقاط ٣٦ سؤال (٢٠٠/٤٠٠/٦٠٠):** حروف لعبة وصل خلايا، مو نقاط. نبقي آليتنا.
- **أسماء وسائل المساعدة في المستند:** نصمم وسائلنا بأسماء خاصة (تحت).

## المراحل

### المرحلة ١: اللعبة الأساسية ✅ (جاهزة على جهاز واحد)
لوحة سداسية، ٦ فئات، فريقان، تلميحات، جرس، مهلة، كشف، «أي فريق جاوب صح؟»، تراجع، ٣ من ٥، أصوات، تسجيل دخول (ينتظر الإعداد).

### المرحلة ٢: لعبة حقيقية أونلاين
- [ ] نقل الأسئلة إلى Supabase (سكربت استيراد من `data/questions.json`، المدقق فقط).
- [ ] **حفظ واستكمال اللعبة:** حالة اللعبة في قاعدة البيانات بعد كل خطوة، وصفحة «ألعابي السابقة».
- [ ] **Snapshot:** نسخة من الأسئلة عند بدء اللعبة، عشان تعديل سؤال ما يغيّر لعبة قائمة.
- [ ] **عدم تكرار الأسئلة بين الألعاب:** سجل الأسئلة اللي ظهرت لكل حساب، والأولوية لغير المكرر.
- [ ] **جرس الجوال بالباركود** (Realtime) مع العدالة على الخادم.
- [ ] **حالة اللعبة كـ State Machine** على الخادم (مسودة، جارية، سؤال مفتوح، الجواب مكشوف، موقوفة، منتهية).
- [ ] شاشة نهاية المباراة: إحصائيات، أفضل فئة لكل فريق، ومشاركة صورة النتيجة.

### المرحلة ٣: وسائل المساعدة (أسماء حروف الخاصة، تتفعل من `config.ts`)
| الوسيلة | متى | الأثر |
|---|---|---|
| تلميح إضافي | بعد ظهور السؤال | يكشف تلميح زيادة |
| غيّر السؤال | بعد ظهور السؤال | سؤال ثاني بنفس الحرف |
| اتصال بصديق | بعد ظهور السؤال | مؤقت ٣٠ ثانية |
| جوابين | بعد ظهور السؤال | الفريق يقول إجابتين، وتنحسب لو وحدة صح |
| قفل خلية | قبل اختيار الحرف | يقفل خلية على الخصم لمدة سؤالين |
| **سرقة الخلية** و **الخلية الذهبية** | (موجودة في الإعدادات) | |
كل فريق يختار ٣ وسائل عند الإعداد، وكل وسيلة مرة وحدة، والتحقق على الخادم.

### المرحلة ٤: أنواع أسئلة إضافية
- [ ] صورة («من هو المشهور؟» جاهز في الكود، ينتظر مصدر صور مرخّص).
- [ ] خريطة.
- [ ] صوت (مقطع قصير بحقوق سليمة).
- [ ] عدد حروف الإجابة كتلميح (يناسب حروف جداً).
- [ ] الإبلاغ عن سؤال خاطئ من داخل اللعبة.

### المرحلة ٥: المتجر والهدايا (تحتاج قرار تجاري)
- [ ] رصيد ألعاب، باقات، كوبونات، وسجل حركات (الرصيد يُحجز عند بدء اللعبة فقط، ولا يُخصم مرتين).
- [ ] الدفع: KNET وبطاقات عبر مزود مرخّص (مثل MyFatoorah أو Tap) **للويب**. **تطبيق iOS** يلزمه Apple In-App Purchase للمشتريات الرقمية، و**Android** يلزمه Google Play Billing.
- [ ] الرصيد ما ينضاف إلا بعد تأكيد الدفع من الخادم (Webhook موقّع، ومفتاح منع التكرار).
- [ ] الهدايا: رمز فريد يُستخدم مرة وحدة.

### المرحلة ٦: لوحة الإدارة
- [ ] إدارة الأسئلة: إضافة، تعديل، رفع وسائط، استيراد Excel/CSV، اكتشاف التكرار (المدقق الحالي)، اعتماد ونشر، بلاغات.
- [ ] إدارة الفئات والباقات والمستخدمين والمدفوعات.
- [ ] صلاحيات: مدير عام، محرر محتوى، مالية، دعم فني.
- [ ] لوحة إحصائيات.

### المرحلة ٧: الجودة والنشر
- [ ] اختبارات (وحدات، تكامل، من البداية للنهاية).
- [ ] سياسة الخصوصية والشروط، وحذف الحساب (مطلوب من Apple و Google).
- [ ] PWA ثم تطبيقات المتاجر (Capacitor).

## قرارات تجارية مطلوبة من المستخدم
1. **نموذج الدخل:** مجاني بالكامل؟ عدد ألعاب مجانية ثم دفع؟ اشتراك؟ دفع لكل لعبة؟
2. **الأسعار** لو فيه دفع.
3. **مزود الدفع** في الكويت (يحتاج سجل تجاري وحساب تاجر).
4. **الهدايا:** نبيها في الإصدار الأول ولا بعدين؟
